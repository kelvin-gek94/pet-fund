# Pet Fund Cash Flow Tracker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A private, phone-first web app where 5 siblings track a shared pet fund — contributions, expenses, out-of-pocket claims, upcoming costs, runway, WhatsApp summaries and backups.

**Architecture:** Static site (no build step) using native ES modules, hosted on GitHub Pages, talking directly to a dedicated Supabase project secured by Google sign-in + an email allowlist enforced with Row Level Security. All money/date logic lives in pure modules (`calc.js`, `dates.js`, `summary.js`) tested in a browser test page; UI modules are thin.

**Tech Stack:** HTML/CSS/vanilla JS (ES modules), Supabase JS 2.117.2 (pinned), JSZip 3 (`https://cdn.jsdelivr.net/npm/jszip@3.10.1/+esm`), Supabase Postgres + Auth (Google) + Storage, GitHub Pages, GitHub Actions. Local dev server: PowerShell `HttpListener` script (no Node/Python on this PC).

**Spec:** `docs/superpowers/specs/2026-10-03-pet-fund-design.md`

## Global Constraints

- Currency RM only; display as `RM 1,234.50`. All arithmetic in **integer cents**; convert at the DB boundary.
- Dates are `YYYY-MM-DD` strings in **Malaysia time (UTC+8)**; never derive "today" from `toISOString()`.
- Members: Kelvin, Vincent, Desmond, Jolyn, Dickson. Pets: Murphy, Panda, Watson, Mochi, Poppy. Categories: Food, Vet, Grooming, Medication, Supplies, Insurance, Other.
- **No email addresses, data, or service-role key in the repo** (repo is public). `schema.sql` seeds members with `email = null`.
- No hard deletes: rows are soft-deleted via `deleted_at`; every calculation ignores soft-deleted rows.
- Summary text table lines ≤ 30 characters, wrapped in ``` fences.
- Upcoming "due soon" window = 7 days; receipt signed URLs expire after 600 s; receipts resized to max 1600 px long edge, JPEG quality 0.8.
- Backup reminder shown only to the member named Kelvin, when `last_backup_at` is null or > 7 days old.
- Keep-alive ping every 3 days.
- Phone-first: layout must work at 375 px wide with no horizontal scroll.
- Commits: repo-local identity (GitHub noreply email), messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Floating-point money** — `0.10 + 0.20` style sums and Supabase returning `numeric` as strings ("12.30"). Expect exact cents. → Task 1 tests `toCents`/`sumCents`.
2. **Timezone "today"** — at 07:00 in Malaysia, UTC is still yesterday; "this month" and "due soon" must use local date. → Task 1 test `todayMY`.
3. **Claim crosses months** — expense dated 28 Sep paid by Jolyn, reimbursed 3 Oct: Sep spend includes it; cash drops only from 3 Oct; pending until reimbursed. → Task 2 test.
4. **Long names / big amounts in summary** — a pet/category name of 20 chars or an amount ≥ RM 10,000 must not push a line past 30 chars (truncate name with "…"). → Task 3 test.
5. **Non-member Google account** — signs in successfully at Google but must see "Not authorised", be signed out, and RLS must return 0 rows / reject insert. → Task 5 gate + Task 13 RLS check.

### Task 2: Fund calculations (`calc.js`)

**Files:** Create `js/calc.js`, `tests/calc.test.js`

**Interfaces:**
- Consumes: Task 1 helpers; `Txn`, `Upcoming`, `Member` shapes.
- Produces (all ignore `deleted_at != null`):
  - `cashInFund(txns, openingCents): int` = opening + contributions − fund-paid expenses − expenses with `reimbursed_on`
  - `pendingClaims(txns): {member_id, total_cents, count, oldest_date}[]` (sorted by total desc)
  - `availableCents(txns, openingCents): int` = cash − Σ pending
  - `spendInMonth(txns, 'YYYY-MM'): int` (all expenses by `date`, claims included)
  - `avgMonthlySpend(txns, today): int` — mean over those `previousMonths(today,3)` that are ≥ the month of the earliest non-deleted transaction (fresh-start rule); if none of those months qualify, return `spendInMonth(current month)`
  - `runway(availableCents, reserveCents, avgCents): {months: number|null, belowReserve: boolean}` — `months = null` when avg = 0; else `max(0, (available − reserve)/avg)` rounded to 1 decimal; `belowReserve = available < reserve`
  - `contributionsInMonth(txns, members, 'YYYY-MM'): {member_id, name, total_cents}[]` — active members only, in members order, 0 if none
  - `dueSoon(upcoming, today, days=7): (Upcoming & {overdue:boolean})[]` — active, `next_due <= today+days`, sorted by `next_due`
  - `nextDueAfterPaid(item: Upcoming): 'YYYY-MM-DD'` — monthly +1, every_n_months +every_n, yearly +12, via `addMonthsClamped`
  - `spendBy(txns, field: 'category_id'|'pet_id', from, to): Map<id|null, int>` (inclusive dates)
  - `inOutByMonth(txns, fromMonth, toMonth): {month, in_cents, out_cents}[]`

- [ ] **Step 1: Write failing tests** with a fixture: opening 10000; contributions Kelvin 20000 (2026-09-05), Vincent 15000 (2026-10-01); fund expense 5000 Vet Mochi (2026-09-10); claim Jolyn 12000 Food (2026-09-28, reimbursed 2026-10-03); claim Desmond 3000 (2026-10-02, pending); a soft-deleted contribution 99999.

```js
assertEqual(cashInFund(T, 10000), 10000+20000+15000-5000-12000);   // 28000
assertDeep(pendingClaims(T).map(c=>[c.member_id,c.total_cents,c.count]), [['desmond',3000,1]]);
assertEqual(availableCents(T, 10000), 25000);
assertEqual(spendInMonth(T,'2026-09'), 17000);          // claim counts on expense date
assertEqual(spendInMonth(T,'2026-10'), 3000);
assertDeep(runway(25000, 20000, 10000), {months:0.5, belowReserve:false});
assertDeep(runway(15000, 20000, 10000), {months:0,   belowReserve:true});
assertDeep(runway(25000, 0, 0),         {months:null, belowReserve:false});
// fresh start: first txn in Sep, today 2026-10-03 → only Sep qualifies → avg = 17000
assertEqual(avgMonthlySpend(T,'2026-10-03'), 17000);
// no complete month yet → current month to date
assertEqual(avgMonthlySpend(T.filter(t=>t.date>='2026-10-01'),'2026-10-03'), 3000);
// contributionsInMonth Oct: Kelvin 0, Vincent 15000, … all 5 present
// dueSoon: item due 2026-10-01 → overdue:true; due 2026-10-10 → included; 2026-10-11 → excluded (today 2026-10-03)
assertEqual(nextDueAfterPaid({frequency:'every_n_months',every_n:3,next_due:'2026-11-30'}), '2027-02-28');
```
